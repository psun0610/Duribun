# 작업 규칙

## 응답과 커밋

- 사용자 응답은 **한국어**로 합니다.
- 커밋 메시지는 한국어 + 프리픽스: `[Init]` `[Feat]` `[Fix]` `[Hotfix]` `[Chore]` `[Perf]`.
- 제목 아래에는 `### 상세 작업 내용` 불릿을 붙입니다. 형식은 `docs/commit-message.md` 참조.
- 커밋/푸시는 사용자가 요청할 때만 합니다.

## 변경 규율

- 요청을 푸는 가장 작은 일관된 변경만 합니다. 내가 만들지 않은 변경은 되돌리지 않습니다.
- 새 의존성 추가는 명시적 승인 없이 하지 않습니다. `docs/frontend.md`가 Zustand를 언급하지만 **실제로 설치되어 있지 않습니다** — 공유 상태가 필요해지면 먼저 물어보세요. (`server-only`도 없습니다.)
- 광범위한 리팩터링은 사용자가 요청했거나 변경에 반드시 필요할 때만 합니다.

## 검증

1. `pnpm lint` (경고 2개는 기존부터 있던 것, 오류는 0이어야 합니다)
2. `pnpm typecheck`
3. `pnpm test` — **전체를 돌립니다.** 파일을 지정해 일부만 돌리면 다른 곳이 깨진 걸 놓칩니다. 실제로 그렇게 놓친 적이 있습니다.
4. 라우트·페이지를 건드렸다면 `pnpm build`까지

DB 스키마를 건드렸다면 위로는 부족합니다 — `.claude/rules/supabase.md` 참조.
UI 동작은 테스트로 확인되지 않습니다. 실기기/브라우저 확인을 못 했다면 그 사실을 사용자에게 말하세요.
검사를 돌릴 수 없다면 이유와 남은 리스크를 말합니다.
